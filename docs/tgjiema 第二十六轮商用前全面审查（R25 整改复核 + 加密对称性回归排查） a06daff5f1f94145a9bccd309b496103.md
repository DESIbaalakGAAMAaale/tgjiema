## 三、本轮新发现

### 🟠 R26-M1（低危 / 数据一致性）：R2 密钥加密不对称——写入加密但无解密读取器

- **结论**：P2-4 的整改把 admin `/set_r2` 流程写入 config 表的 `r2_secret_key` 改为 Fernet 密文，但**全仓找不到与之对称的解密读取路径**，与 relay api_hash 的成熟做法不一致。
- **证据**：
    - **写入端（已加密）**：`conversation.py` 两条路径均 `await set_config("r2_secret_key", _encrypt_secret(...))`。
    - **relay 的对称范式（正确对照）**：`session.py` `set_relay_config` 加密写入、`get_relay_config` 读取时 `decrypt(api_hash)`——成对存在。
    - **R2 消费端（全部读明文 .env，不读 config 表）**：`r2.py init_r2`、`db_backup.py` 的 `run_db_backup` / `list_backups` / `restore_from_backup` 均从 `settings.R2_SECRET_ACCESS_KEY`（pydantic .env）取值并 `r2_storage.configure(...)`；**无一处 `get_config("r2_secret_key")`**，也不存在 `get_r2_config()` 解密器。
- **影响分析（二选一，均需处理）**：
    1. 若 config 表的 R2 凭证本就**无运行时消费**（R2 完全由 .env 驱动）→ 该加密为**装饰性/死配置**，admin `/set_r2` 设置的凭证从不生效（被 .env 覆盖）——功能预期与实现不符。
    2. 若未来/别处新增读取 config 表 `r2_secret_key` 的消费者且未解密 → 会拿到 Fernet 密文作为 SigV4 签名密钥 → R2 全部请求 `403 SignatureDoesNotMatch`——**潜在功能回归**。
- **建议**：
    - 与 relay 对齐，新增 `get_r2_config()` 在读取 `r2_secret_key` 时 `decrypt`，并让 `/set_r2` 配置真正参与 `r2_storage.configure`（若产品意图是运行时可配）；
    - 或明确 R2 仅由 .env 驱动，则回退该字段加密（避免死配置误导），并在 `/set_r2` 文案标注「仅记录/展示」。
    - 无论哪条，务必补一条「加密→解密→SigV4 签名」的端到端冒烟测试。
- **定级理由**：生产 R2 凭证走 .env、始终可用，备份主链路不受影响，故为低危；但属「改了一半」的不对称改动，需闭环。

## 四、VERIFIED-OK 亮点（本轮实证）

- **`$addToSet` 数据库层实现严谨**：`CASE WHEN 空 THEN 建数组 WHEN NOT (@> 包含) THEN 拼接 ELSE 原值`，参数化占位、`_validate_identifier` 白名单校验列名，去重语义正确，无注入面。
- **`code_generator` 热路径瘦身**：每次建码从「7×多条 INFO 日志 + 冗余内层循环」降为「1 条 debug」，显著降低高频路径日志开销与 PII 暴露面；`_generate_random_id` 仍为 `secrets.randbelow` 密码学安全随机，36¹² 空间 + DB 主键兜底。
- **`relay_db` 加密层（PRE-10）稳健**：`encrypt/decrypt` 失败一律抛 `RuntimeError`，绝不静默回退明文；密钥缺失/格式非法给出可操作的运维指引。
- **HSTS 与既有安全头协同**：nosniff / X-Frame-Options:DENY / Referrer-Policy / HSTS 齐备，配合自动 `CSRF_COOKIE_SECURE=1` + `.env` chmod 600，TLS 部署闭环完善。
- **备份脱敏策略自洽**：`_SENSITIVE_FIELDS=set()`（P0-3）确保备份保留真实凭证、恢复后可用；`_redact_secrets` 保留按 `config_key` 行级脱敏能力以备未来启用。
- **CDN 缓存陷阱已规避**：本轮以 commit SHA 锚定取证，避免了 `raw.githubusercontent.com` 陈旧缓存导致的误判（初次拉取曾命中旧版本，已纠正）。
