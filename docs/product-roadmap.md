# R39 P2-9/10: 产品功能整体优化路线图

> 基于 R39 报告 §9 "产品功能整体优化建议" 整理为可执行路线图。
> 本文档跟踪 §9.1~§9.4 的产品优化建议,按优先级与季度规划。

---

## 1. 用户体验优化 (§9.1)

### 1.1 统一任务中心

**目标**: 用户可在单一界面查看所有任务状态(上传/索引/复制/取件/失败重试)。

| 功能 | 优先级 | 季度 | 状态 |
| ---- | ------ | ---- | ---- |
| 任务列表 `/tasks` 命令 | P1 | Q3 2026 | 🔲 待规划 |
| 任务状态: pending/in_progress/completed/failed | P1 | Q3 2026 | 🔲 待规划 |
| 预计完成时间(基于历史 P99 延迟) | P2 | Q4 2026 | 🔲 待规划 |
| 失败任务一键重试按钮 | P2 | Q4 2026 | 🔲 待规划 |
| 任务详情(文件清单 + 投递目标) | P2 | Q4 2026 | 🔲 待规划 |

### 1.2 上传回执

**目标**: 上传完成后返回结构化回执,便于用户追踪。

| 功能 | 优先级 | 季度 | 状态 |
| ---- | ------ | ---- | ---- |
| 返回 upload_id | P1 | Q3 2026 | 🔲 待规划 |
| 返回文件数 + 总大小 | P1 | Q3 2026 | 🔲 待规划 |
| 返回保护级别(TTL/密码) | P2 | Q3 2026 | 🔲 待规划 |
| `/status <upload_id>` 查询命令 | P1 | Q3 2026 | 🔲 待规划 |
| 主副本状态(已镜像/镜像中/失败) | P2 | Q4 2026 | 🔲 待规划 |

### 1.3 文件集合与目录

**目标**: 支持文件集合码、分页、批量下载。

| 功能 | 优先级 | 季度 | 状态 |
| ---- | ------ | ---- | ---- |
| 集合码(一个码对应多个文件) | P1 | Q4 2026 | 🔲 待规划 |
| 集合分页浏览(inline button) | P2 | Q4 2026 | 🔲 待规划 |
| 批量下载(媒体组发送) | P1 | Q4 2026 | 🔲 待规划 |
| 集合版本更新(同一码追加文件) | P2 | Q1 2027 | 🔲 待规划 |
| 部分失效提示(集合中部分文件已删除) | P2 | Q1 2027 | 🔲 待规划 |

### 1.4 可靠通知

**目标**: 关键事件主动通知用户。

| 事件 | 通知方式 | 优先级 | 季度 |
| ---- | -------- | ------ | ---- |
| 文件 READY(索引完成) | Telegram 消息 | P1 | Q3 2026 |
| R100 延迟提醒(副本降级) | Telegram 消息 | P2 | Q4 2026 |
| 副本不足告警(因子 < 3) | Admin 告警 + 用户提示 | P2 | Q4 2026 |
| 文件过期前提醒(TTL 剩 24h) | Telegram 消息 | P1 | Q3 2026 |
| 恢复完成通知(失效码已修复) | Telegram 消息 | P2 | Q4 2026 |

### 1.5 用户自助修复

**目标**: 用户可自助修复失效文件码,无需联系客服。

| 功能 | 优先级 | 季度 | 状态 |
| ---- | ------ | ---- | ---- |
| `/repair <code>` 重新索引命令 | P1 | Q4 2026 | 🔲 待规划 |
| `/regenerate <code>` 重新生成码命令 | P2 | Q1 2027 | 🔲 待规划 |
| 失败原因查看(不暴露内部频道信息) | P1 | Q4 2026 | 🔲 待规划 |
| 修复进度查询 | P2 | Q1 2027 | 🔲 待规划 |

### 1.6 国际化与无障碍

**目标**: 支持中英双语,统一错误码,按钮式流程。

| 功能 | 优先级 | 季度 | 状态 |
| ---- | ------ | ---- | ---- |
| 中文/英文语言包 | P2 | Q1 2027 | 🔲 待规划 |
| `/lang en` 切换语言 | P2 | Q1 2027 | 🔲 待规划 |
| 统一错误码(如 ERR_FILE_NOT_FOUND) | P1 | Q4 2026 | 🔲 待规划 |
| 按钮式流程(inline keyboard 替代命令输入) | P1 | Q4 2026 | 🔲 待规划 |

## 2. 商业化与权限 (§9.2)

### 2.1 套餐与配额

**目标**: 通过 entitlement service 统一判定配额。

| 功能 | 优先级 | 季度 | 状态 |
| ---- | ------ | ---- | ---- |
| Entitlement service(套餐判定) | P1 | Q4 2026 | 🔲 待规划 |
| 套餐: 免费/Pro/Enterprise | P1 | Q4 2026 | 🔲 待规划 |
| 配额: 文件大小上限 | P1 | Q4 2026 | 🔲 待规划 |
| 配额: 并发上传数 | P2 | Q1 2027 | 🔲 待规划 |
| 配额: 保留期(7天/30天/永久) | P1 | Q4 2026 | 🔲 待规划 |
| 优先队列(Pro 用户优先投递) | P2 | Q1 2027 | 🔲 待规划 |

### 2.2 Quota Ledger

**目标**: 配额使用 reservation/settlement/refund 模型,防止超卖。

| 功能 | 优先级 | 季度 | 状态 |
| ---- | ------ | ---- | ---- |
| Quota reservation(上传前预扣) | P1 | Q4 2026 | 🔲 待规划 |
| Quota settlement(完成后结算) | P1 | Q4 2026 | 🔲 待规划 |
| Quota refund(失败时退还) | P1 | Q4 2026 | 🔲 待规划 |
| Quota ledger 表(不可篡改审计) | P2 | Q1 2027 | 🔲 待规划 |

### 2.3 管理端 RBAC

**目标**: 分权管理,降低单点风险。

| 角色 | 权限 | 优先级 | 季度 |
| ---- | ---- | ------ | ---- |
| 运营 | 用户管理、文件管理、码生成 | P1 | Q4 2026 |
| 客服 | 查看用户、查看文件、修复码 | P1 | Q4 2026 |
| 运维 | 系统配置、备份、迁移 | P1 | Q4 2026 |
| 安全 | 审计日志、权限审查 | P2 | Q1 2027 |
| 超级管理员 | 全部权限 + 角色管理 | P1 | Q4 2026 |

### 2.4 高风险操作

| 功能 | 优先级 | 季度 |
| ---- | ------ | ---- |
| 二次确认(删除/批量操作) | P1 | Q4 2026 |
| 审批流程(高风险需另一管理员审批) | P2 | Q1 2027 |
| 不可篡改审计日志(append-only) | P1 | Q4 2026 |

## 5. 季度规划总览

| 季度 | 重点方向 | 关键交付 |
| ---- | -------- | -------- |
| Q3 2026 | 用户体验基础 | 统一任务中心、上传回执、READY 通知、过期提醒 |
| Q4 2026 | 商业化与权限 | Entitlement service、套餐配额、RBAC、运维控制台、RU 成本中心 |
| Q1 2027 | 高级功能 | 集合版本、批量下载、灾备演练、国际化、数据导出 |
| Q2 2027 | 安全与合规 | 恶意内容扫描、隐私政策、举报闭环完善 |

---

## 6. 优先级定义

| 优先级 | 含义 | 触发条件 |
| ------ | ---- | -------- |
| P1 | 必须实现 | 影响核心功能或安全 |
| P2 | 应该实现 | 提升用户体验或运维效率 |
| P3 | 可以实现 | 锦上添花,资源允许时实现 |
