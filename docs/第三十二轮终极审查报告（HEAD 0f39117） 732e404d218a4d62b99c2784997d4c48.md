## 二、🟡 R32-1（新发现，真实潜伏 Bug）：[display.py](http://display.py) 未导入 logger

**文件：** `bots/admin_bot/display.py`

**问题：** 该文件在三个 `except` 兜底分支中调用了 `logger.warning(...)`：

- `_get_cells_cached`
- `_get_topology_text`
- `_get_relay_status_text`

但文件顶部 import 段**没有** `from loguru import logger`（顶部仅导入 asyncio/datetime/re/time、config.settings、database 相关、utils 若干）。

**后果：** 正常路径不受影响；一旦这三个函数进入异常兜底分支，`logger.warning(...)` 会抛出 `NameError: name 'logger' is not defined`，把一个**本应被捕获降级**的错误升级为**未捕获崩溃**。其中 `/topology`（`action:topology`）由管理员频繁调用，暴露面最大——即当拓扑读取本身出错时，兜底日志反而让请求彻底失败。

**佐证（对比同类文件）：** 本轮验证 `database/cache_store.py` 第 6 行确有 `from loguru import logger`，其内部同样的 `logger.warning(...)` 兜底完全正常；`utils/force_join.py` 也正确导入。唯独 `display.py` 遗漏。

**修复建议：** 在 `display.py` 顶部加入：

```python
from loguru import logger
```

（或将三处 `logger.warning` 改为已导入的日志渠道。）修复成本极低但必须做。

## 三、🟢 R32-2 / R32-3：部署脚本低危硬化建议

**R32-3（🟢 低）——supervisor 版结尾提示 `http://localhost:9001 (默认无密码)`。**

脚本本身并未在配置里启用 `inet_http_server`，故 9001 面板实际未必开启；但该提示文案容易误导运维以为存在一个无鉴权的 Web 面板。建议删除该行，或明确写“如需启用 9001 面板务必设置 username/password”。

> 说明：以上两项**不影响 Docker 与 systemd（per_bot / 单体）三种主推部署路径**，仅针对 supervisor 备选路径，故定为低危。
