## 一、N26-1 · `factory_reset` 清空本地缓存 — 🟢 已确认真实修复

`bots/admin_bot/handlers.py` 的 `factory_reset` 在 CRDB `DELETE FROM` 循环之后，新增独立 aiosqlite 段清空 `data/cache_store.db` 的本地缓存表：

```python
# 同步清空本地 SQLite 缓存，防止脏行回写重新推回 CRDB
sqlite_cleared = []
try:
    import aiosqlite
    from pathlib import Path
    db_path = Path(__file__).parent.parent.parent / "data" / "cache_store.db"
    async with aiosqlite.connect(str(db_path)) as local_db:
        local_tables = [
            "cells_local", "file_records_local", "users_local",
            "codes_local", "local_job_queue", "spare_pool_local",
            "backup_config_local", "code_bot_mapping_local",
            "external_code_mapping_local", "message_backups_local",
            "relay_accounts_local", "rotation_config_local",
        ]
        for tbl in local_tables:
            try:
                await local_db.execute(f"DELETE FROM {tbl}")
                sqlite_cleared.append(tbl)
            except Exception:
                pass  # 表可能不存在，忽略
        await local_db.commit()
```

**核验结论：**

- 带 `crdb_synced` 脏标记、会回写 CRDB 的 **6 张关键表全部覆盖**：`cells_local` / `file_records_local` / `users_local` / `codes_local` / `local_job_queue` / `external_code_mapping_local`。→ 「脏行回写抵消重置」的隐患已消除。
- 表名来自硬编码白名单，`f"DELETE FROM {tbl}"` 无外部输入，无注入风险。
- 数据库路径 `Path(__file__).parent.parent.parent / "data" / "cache_store.db"` 与 `cache_store.py` 的 `DB_PATH` 一致。
- 失败以 `logger.warning` 记录，不影响 CRDB 主流程。

<aside>
ℹ️

**N27-1（提示级，非问题）**：`local_tables` 列表中另有 6 张表（`spare_pool_local` / `backup_config_local` / `code_bot_mapping_local` / `message_backups_local` / `relay_accounts_local` / `rotation_config_local`）在 `cache_store.db` 中并不存在，`DELETE` 会抛异常并被 `except: pass` 静默忽略——功能无害，仅属冗余。可选清理，但不影响上线。
