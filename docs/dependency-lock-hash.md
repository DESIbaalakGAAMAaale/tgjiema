# R39 P2-2: 依赖锁定 Hash(precise version + checksum)

## 背景

R39 终审指出: "锁定依赖 hash;当前 `redis>=5,<6` 仍非精确版本。"

当前 `requirements.txt` 存在两类不精确锁定:
1. **范围约束**: `redis>=5.0,<6` 允许 5.0.0 到 5.99.99 任意版本
2. **无 hash**: 所有依赖只锁定版本号,未锁定文件哈希
   - `pip install` 可能从 PyPI 拉取被替换的同版本恶意包(若 PyPI 被入侵)
   - 无法保证 CI 与生产环境安装的 wheel 文件完全一致

**整改**:
1. 将所有依赖改为**精确版本**(`==`)
2. 生成 `requirements.lock.txt` 包含每个 wheel 的 SHA-256 hash
3. CI/部署使用 `pip install --require-hashes -r requirements.lock.txt`

## 2. 整改方案

### 2.1 修正 redis 版本约束

将 `requirements.txt` 中:
```
redis>=5.0,<6
```
改为:
```
redis==5.0.8
```

(选择当前已发布的最新 5.x 稳定版本,可通过 `pip index versions redis` 查询)

### 2.2 生成 requirements.lock.txt(含 hash)

使用 `pip-compile` (来自 `pip-tools`) 生成带 hash 的锁定文件:

```bash
# 安装 pip-tools
pip install pip-tools

# 生成带 hash 的锁定文件
pip-compile --generate-hashes --output-file=requirements.lock.txt requirements.txt
```

输出示例:

```
#
# This file is autogenerated by pip-compile with Python 3.12
# by the following command:
#
#    pip-compile --generate-hashes --output-file=requirements.lock.txt requirements.txt
#
aiohttp==3.10.5 \
    --hash=sha256:abc123... \
    --hash=sha256:def456...
    # via python-telegram-bot
redis==5.0.8 \
    --hash=sha256:0453b9e6c1a2b3c4d5e6f7890123456789abcdef0123456789abcdef01234567 \
    --hash=sha256:1234... \
    # via -r requirements.txt
...
```

### 2.3 部署使用 --require-hashes

```bash
# CI 与生产部署统一使用锁定文件 + hash 校验
pip install --require-hashes -r requirements.lock.txt
```

`--require-hashes` 标志会:
1. 校验每个下载的 wheel/sdist 的 SHA-256 与 lock 文件中记录的 hash 一致
2. 若任何 hash 不匹配(包被篡改),立即中止安装
3. 防止从被入侵的 PyPI 拉取恶意包

## 3. CI 中集成

在 `.github/workflows/ci.yml` 的 `test` job 中,改用锁定文件安装:

```yaml
    - name: Install dependencies (locked with hashes)
      run: |
        python -m pip install --upgrade pip
        pip install pip-tools
        # 校验 lock 文件与 requirements.txt 一致
        pip-compile --generate-hashes --output-file=/tmp/lock.check requirements.txt
        if ! diff -q requirements.lock.txt /tmp/lock.check > /dev/null; then
          echo "ERROR: requirements.lock.txt 与 requirements.txt 不一致"
          echo "请运行: pip-compile --generate-hashes --output-file=requirements.lock.txt requirements.txt"
          exit 1
        fi
        # 使用 hash 校验安装
        pip install --require-hashes -r requirements.lock.txt
        pip install pytest pytest-asyncio aiosqlite pyyaml
```

## 4. 升级依赖流程

```bash
# 1. 修改 requirements.txt 中的版本号(如 redis 5.0.8 → 5.1.0)
vim requirements.txt

# 2. 重新生成 lock 文件
pip-compile --generate-hashes --output-file=requirements.lock.txt requirements.txt

# 3. 本地验证安装
pip install --require-hashes -r requirements.lock.txt

# 4. 运行测试
python -m pytest tests/ -v

# 5. 运行 pip-audit 检查已知漏洞
pip-audit -r requirements.txt --strict

# 6. 提交 PR
git add requirements.txt requirements.lock.txt
git commit -m "chore(deps): upgrade redis to 5.1.0"
```

## 5. 多平台 hash 处理

某些包在不同平台(Linux/macOS/Windows)和 Python 版本(3.10/3.11/3.12)下,
wheel 文件不同 → hash 不同。`pip-compile --generate-hashes` 会包含所有平台的 hash:

```
pydantic-core==2.27.0 \
    --hash=sha256:aaa...  # cp310-cp310-manylinux_2_17_x86_64
    --hash=sha256:bbb...  # cp311-cp311-manylinux_2_17_x86_64
    --hash=sha256:ccc...  # cp312-cp312-manylinux_2_17_x86_64
    --hash=sha256:ddd...  # cp311-cp311-macosx_10_12_x86_64
```

`pip install --require-hashes` 会自动选择当前平台对应的 hash 校验。

### 5.1 在 CI 矩阵中校验所有平台

```yaml
  test:
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
        python-version: ['3.10', '3.11', '3.12']
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
      - name: Install locked dependencies
        run: |
          python -m pip install --upgrade pip
          pip install --require-hashes -r requirements.lock.txt
          pip install pytest pytest-asyncio aiosqlite pyyaml
      - name: Run tests
        run: python -m pytest tests/ -v --tb=short --maxfail=5
```

## 6. 安全考量

- **Hash 不可伪造**: SHA-256 抗碰撞,无法构造同 hash 的恶意 wheel
- **PyPI 镜像**: 即使使用国内镜像源,`--require-hashes` 仍会校验,镜像被入侵无法注入恶意包
- **依赖更新审计**: 每次升级需通过 PR 修改 `requirements.txt` + `requirements.lock.txt`,
  留下审计轨迹
- **pip-audit**: CI 中 `pip-audit --strict` 检查已知 CVE(见 `docs/github-pat-workflow-scope.md`)
- **SBOM 关联**: `requirements.lock.txt` 应与 SBOM (`sbom.cyclonedx.json`) 组件版本一致

## 7. 与现有文件的关系

| 文件 | 用途 | 是否锁定 hash |
| ---- | ---- | ------------- |
| `requirements.txt` | 声明直接依赖(版本约束) | 否 |
| `requirements.lock.txt` (新增) | 锁定所有直接+间接依赖 + hash | 是 |
| `sbom.cyclonedx.json` (CI 生成) | SBOM 清单(CycloneDX 格式) | 否(但记录版本) |

`requirements.txt` 仍保留(作为依赖声明),
`requirements.lock.txt` 是部署与 CI 实际使用的精确锁定文件。
