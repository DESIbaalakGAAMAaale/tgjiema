## 一、频道冗余环操作指南

### 1.1 架构概述

系统采用**环形冗余架构**:多个存储频道组成环形链表,每个逻辑文件在多个频道中存有副本。某个频道失效时,自动降级到下一个频道,并新建频道补位。

**核心机制**:
- **Manifest 驱动**:每条文件消息写入存储频道时,同步登记到 `manifest` 表(`file_unique_id` + `channel_id` + `message_id`),作为副本重建的清单
- **免中继账号**:补位频道重建副本时,Bot 按 manifest 清单从存活频道 `copyMessages`,不需要用户账号读历史
- **实时维护**:Mon Bot 作为所有频道的 admin,实时监听新消息并登记 manifest

### 1.2 频道状态说明

| 状态 | 含义 | 投递优先级 |
|------|------|-----------|
| `active` | 当前活跃频道,新文件写入目标 | 最高 |
| `shadow1` | 一级影子(近期轮转降级) | 中 |
| `shadow2` | 二级影子(更早降级或恢复) | 低 |
| `r100` | R100 归档频道(仅存档,不投递) | 不投递 |
| `lost` | 已失效(被封禁/掉线) | 不投递 |

### 1.3 日常运维操作

#### 添加备用频道到池中

当系统频道不足时,需提前准备备用频道并添加到备用池:

```
/spare_add <频道ID> [账号名]
```

- **频道ID**:Telegram 频道的 `-100...` 格式 ID
- **账号名**(可选):指定该备用频道归属的账号名,补位时优先用同账号的备用频道
- **前提**:Mon Bot 必须是该频道的 admin(有发送消息权限)
- **效果**:频道进入备用池,当某个 active/shadow 频道被封禁时自动补位

#### 查看备用池状态

```
/spare_list
```

显示所有备用频道的:频道 ID、是否已用、归属账号。

#### 移除备用频道

```
/spare_remove <频道ID>
```

从备用池移除未使用的备用频道(已投入使用的无法移除)。

#### 添加频道槽位

手动向环形拓扑添加一个槽位:

```
/cell_add <slot_id> <channel_id> [账号名] [状态]
```

- **slot_id**:槽位标识(如 `g1a`、`g1s1`)
- **channel_id**:频道 ID
- **账号名**:归属账号
- **状态**(可选):`active`/`shadow1`/`shadow2`/`r100`,默认 `shadow1`

#### 移除频道槽位

```
/cell_remove <slot_id>
```

- 拒绝移除 `active` 状态的槽位(需先轮转为 shadow)
- 自动修复环形链表前后指针

#### 查看拓扑结构

```
/topology
```

显示完整的环形拓扑:每个槽位的 slot_id、频道 ID、状态、文件数、账号归属、前后指针。

### 1.4 自动降级与补位流程

系统**全自动**处理频道失效,无需人工干预:

```
频道被封禁
  ↓
Mon Bot 心跳检测失败(匹配封禁关键词:channel private/bot was kicked 等)
  ↓
_handle_channel_ban 触发:
  ├── 优先从同账号备用池补充(get_spare_for_account)
  ├── 无同账号备用则从通用备用池补充(get_any_spare)
  └── 无可用备用则降级为 lost,通知管理员添加备用频道
  ↓
替换 channel_id,保持 status 不变,重置 file_count
  ↓
Dsp Bot 发送失败兜底:60s 内失败 N 次自动降级(Mon 不可用时)
```

### 1.5 副本重建(Manifest 驱动)

补位频道补齐存量文件的流程:

```
新频道补位成功
  ↓
Mon Bot 自动触发 auto_fill_new_channels
  ↓
查询 manifest 表:找出 Active 有但新频道缺失的 file_unique_id
  ↓
从存活 peer 频道 copyMessages 到新频道:
  ├── 按 media_group_id 分组保持相册形态
  ├── 批量 20-30 条/轮 + 固定 sleep 限流
  ├── 遇 FloodWait 按返回秒数退避重试(3 次)
  └── 幂等:已存在则跳过(断点续传)
  ↓
更新 manifest 表:登记新频道中的 message_id
```

### 1.6 轮转配置

```
/rotation_set <参数名> <值>
/rotation_view
```

可调参数:

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `active_window_size` | 5 | 同时活跃的 active 槽位数 |
| `files_per_slot` | 500 | 每个槽位文件数达到此值触发轮转 |
| `time_per_slot` | 3600 | 每个槽位运行时间(秒)达到此值触发轮转 |

轮转时,active 槽位降级为 shadow1(保留 `demoted_to_channel_id` 供投递跳转),同组 shadow 槽位升级为 active。

### 1.7 常见运维场景

**场景 1:备用频道不足**
```
/spare_list  → 查看剩余备用
/spare_add <新频道ID> <账号名>  → 补充备用
```

**场景 2:某个频道被封**
- 系统自动降级,无需操作
- 如果备用池耗尽,admin_bot 会收到告警,需添加新备用频道

**场景 3:手动触发频道检查**
```
/health  → 查看所有频道健康状态
/topology  → 查看拓扑完整性
```

**场景 4:数据库恢复后重建**
- 数据库恢复后,manifest 表会随恢复数据重建
- 新上传的文件自动登记 manifest
- 存量文件(恢复前上传的)无 manifest 记录,需通过 Mon Bot 的 `replicate_all_active_to_shadows` 补齐

## 二、Admin Bot 全部功能介绍

Admin Bot 是系统管理后台,仅 `ADMIN_TELEGRAM_ID` 配置的管理员可用。支持命令行和按钮式交互两种操作方式。

### 2.1 启动与菜单

- **`/start`** — 打开管理员主菜单(按钮式交互面板)
- **`/help`** — 显示全部命令列表

主菜单结构:
```
管理员面板
├── 系统状态 → 系统概览 / 健康状态
├── 用户管理 → 用户列表 / 查询 / 等级 / 封禁 / 配额
├── 文件管理 → 文件列表 / 查询 / 删除
├── 解码日志
├── 用户中继 → 状态 / 配置 / 验证码 / 待处理
├── 系统配置 → 存储 / 前缀 / 加群 / 用户名 / 配额 / R2 / 备份
├── 文件码路由 → 新增 / 删除 / 查看
├── Bot 限流 → 新增 / 删除 / 查看
├── 环形拓扑 → 查看
├── 备用池 → 添加 / 移除 / 查看
└── 轮转配置 → 查看 / 修改
```

当用户在 idx_bot/dsp_bot 点击"举报"按钮后,admin_bot 收到举报通知,管理员可通过回调按钮处理:

| 按钮 | 功能 |
|------|------|
| 封禁上传者 | 封禁该文件的上传者 |
| 脱钩文件码 | status=detached,解码返回"文件不存在" |
| 限制举报人 | 写入 blocked_users,举报人无法解码该文件 |
| 忽略 | 不处理 |

### 2.11 数据库恢复

```
/restore [序号] [table:xxx,yyy] [merge:yes]
```

- **序号**:备份列表中的序号(不填则最新)
- **table:xxx,yyy**:只恢复指定表(不填则全量)
- **merge:yes**:增量合并模式(INSERT ON CONFLICT DO NOTHING),默认覆盖模式(TRUNCATE + INSERT)

确认后需点击 `restore:confirm` 按钮二次确认。

## 三、各 Bot 功能模块介绍与操作流程

### 3.1 Idx Bot(解码机器人)

**职责**:生成文件码、处理解码请求、派发投递任务。

#### 命令

| 命令 | 功能 |
|------|------|
| `/start` | 欢迎消息 + 创建用户 + 补发暂存文件码 |
| `/help` | 使用说明(文件码格式、会员权益) |
| `/status` | 会员等级、剩余解码次数、上传权限、外部码配额 |
| `/my_codes [页码]` | 我的文件码列表(分页,每页 12 条) |

#### 解码操作流程

**单个解码**:
```
用户发送文件码 → 校验加群 → 限流 → 检查权限 → 预扣配额 → 写入 jobs 派工表 → 回复"文件将由 @sender 发送"
```

**批量取件**:
```
用户一次发送多个文件码(换行/空格分隔,最多 10 个)
→ 整批一次限流 → 逐个独立消耗配额 → 汇总成功/失败
```

**外部码解码**:
```
用户发送外部码(如 QQfile2_bot:qq10ad1e0200_6V)
→ 查路由映射 → 中继账号发送到目标 Bot → 回传结果 → 派发文件
```

**合集码解码**:
```
用户发送合集码 → 展开子文件码 → 逐个派发 → 合集消耗 1 次配额,子码不额外消耗
```

#### 文件码管理(/my_codes 详情页)

| 按钮 | 功能 |
|------|------|
| 修改备注 | 输入新备注 |
| 设置有效期 | 1/7/30/90 天/自定义/永久 |
| 设置访问次数 | 0=不限,超过后他人无法解码 |
| 下架/恢复 | 控制文件码是否可解码 |
| 查看统计 | 总解码次数、最近解码时间 |
| 翻页 | 浏览全部文件码 |

### 3.2 Up Bot(上传机器人)

**职责**:接收用户上传的文件,存入存储频道,生成文件码。

#### 命令

| 命令 | 功能 |
|------|------|
| `/start` | 欢迎消息,说明三种上传模式 |
| `/start_upload` | 进入批次上传模式 |
| `/end_upload` | 结束批次上传,生成文件码 |
| `/cancel_upload` | 取消批次上传 |
| `/note <备注>` | 为当前批次添加备注 |
| `/cancel_note` | 跳过备注输入 |
| `/new_collection` | 进入合集打包模式 |
| `/end_collection` | 结束合集打包,生成合集码 |
| `/cancel_collection` | 取消合集打包 |
| `/note_collection <备注>` | 为合集添加备注 |

#### 上传流程

**单文件上传**:
```
发送文件 → 选择活跃频道 → 秒传去重(查 file_unique_id)
→ copy_message 到存储频道 → 登记 manifest → 转发 R100 归档
→ 弹出选项:有效期 → 备注 → 转发权限 → 生成文件码
```

**媒体组上传(相册)**:
```
发送多图/多视频 → 自动聚合 media_group_id → copy_messages 批量复制
→ 整组去重 → 选项流程 → 生成文件码
```

**批次上传**:
```
/start_upload → 持续发送文件(支持多次混合类型)
→ /note <备注>(可选)→ /end_upload → 按 media_group_id 分组复制
→ 选项流程 → 生成一个文件码对应全部文件
```

#### 合集打包流程

```
/new_collection → 发送文件码(每行一个或空格分隔,可多次追加)
→ /note_collection <备注>(可选)→ /end_collection
→ 去重保留顺序 → 生成合集码 → 写入 file_records(is_collection=1)
```

合集码发送给解码机器人即可一次性获取全部文件。

### 3.3 Dsp Bot(发送机器人)

**职责**:从 jobs 表轮询任务,通过最佳频道将文件发送给用户。

#### 命令

| 命令 | 功能 |
|------|------|
| `/start` | 欢迎消息 + 标记已启动 + 恢复暂存任务 |

> 用户必须先 `/start` Dsp Bot 才能收到文件。未 /start 前的任务暂存为 `waiting_start` 状态,启动后自动恢复。

#### 发送架构

```
Redis Stream(XREADGROUP 事件驱动) ← 降级 → SQLite dsp_notify 轮询
  ↓
CAS 认领(mark_local_job_dispatched:pending→dispatched)
  ↓
resolve_delivery_channel 解析最佳频道(同组优先 → 跨组兜底)
  ↓
copy_messages 批量发送(保持相册形态)
  ↓
成功 → XACK + 举报按钮
失败 → 沿环形链表找下一个频道(最多 10 个)→ 重试 3 次后标记 dead
```

#### 分页功能

- 单页 `PAGE_SIZE` 条,超出分页发送
- 翻页按钮:首页/上页/页码窗口(8 个)/下页/末页
- 翻页状态保留 5 分钟

#### 降级兜底

Mon Bot 不可用时,Dsp Bot 自主降级:
- 60 秒内失败 N 次(`CHANNEL_FAILURE_THRESHOLD`)触发降级
- 降级后频道 status 置为 `lost`,投递路由自动绕过

### 3.4 Mon Bot(监控机器人)

**职责**:后台监控、自动降级、轮转管理。无用户命令,全自动运行。

#### 监控指标

| 指标 | 告警阈值 |
|------|---------|
| 投递成功率 | <95% WARNING,<80% CRITICAL |
| 队列积压 | >50 WARNING,>200 CRITICAL |
| 中继账号存活率 | <80% WARNING,<50% CRITICAL |
| 中继账号绝对数量 | <RELAY_SAFE_POOL_SIZE(默认 2)CRITICAL |
| Bot 离线 | 离线超 5 分钟 CRITICAL |
| 频道心跳 | active/shadow1/shadow2 槽位 |

#### 告警机制

- 分级:WARNING / CRITICAL
- 冷却:同一事件 10 分钟内不重复
- 恢复通知:告警解除后发送恢复通知
- 通知通道:直接向 `ADMIN_TELEGRAM_ID` 发消息

#### 自动降级

```
心跳检测(每 60s) → get_chat 探测频道
  ↓ 失败
匹配封禁关键词(channel private/bot was kicked)
  ↓ 命中
从备用池补充(同账号优先 → 通用池) → 替换 channel_id
  ↓ 无可用备用
降级为 lost → 通知管理员
```

#### 轮转管理

```
active 槽位满足条件(file_count >= files_per_slot 或 时间 >= time_per_slot)
  ↓
沿环形链表找出 active_window_size 个 active 槽位
  ↓
降级为 shadow1(保留 demoted_to_channel_id)
  ↓
同组 shadow 升级为 active → 修复指针 → 级联处理
```

## 附录:系统架构概览

```
用户
  ↓
Up Bot(上传) → 存储频道(环形冗余) → R100 归档
  ↓
Idx Bot(解码) → jobs 派工表 → Redis Stream / SQLite 通知
  ↓
Dsp Bot(发送) → resolve_delivery_channel → copy_messages → 用户
  ↓
Mon Bot(监控) → 心跳检测 → 自动降级/轮转/补位 → 告警
  ↓
Admin Bot(管理) → 配置/用户/文件/中继/拓扑/备份恢复
```

**数据流**:
- 热路径:全部走 SQLite 本地缓存(零 CRDB RU)
- 冷路径:后台批量同步到 CRDB(TiDB Cloud)
- 备份:定时 dump 到 Cloudflare R2

**技术栈**:
- Bot 框架:python-telegram-bot 21.6(Bot API)
- 用户账号层:Telethon 1.38.0(MTProto,中继账号)
- 数据库:SQLite(本地热路径)+ TiDB Cloud / CockroachDB(VPS)
- 缓存:Redis(Stream 事件驱动,可选)
- 对象存储:Cloudflare R2(数据库备份)
- 加密:cryptography Fernet(api_hash / R2 密钥)
