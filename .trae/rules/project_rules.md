# 项目规则

## 项目架构（长期记忆）
- 本项目共 4 个主机器人 + 若干备份机器人
  - **Bot 1 (upload_bot)**：仅接受用户上传的文件，存入存储频道
  - **Bot 2 (decoder_bot)**：负责生成文件码 + 解码（含内部码和第三方外部码）
  - **Bot 3 (sender_bot)**：仅负责向用户发送文件（唯一出口）
  - **Bot 4 (admin_bot)**：管理员机器人，管理配置、重置等
- 所有向用户发送文件的操作，必须经过 Bot 3 (sender_bot) 的队列机制，Bot 2 解码后只入队不直发

## 文件发送规则（长期记忆）
- 向用户发送文件时，必须以媒体组（media_group）格式批量发送，保持相册/媒体组形式
- 解码第三方机器人时，必须保持原媒体格式（视频、照片、音频等类型），不走下载->重新上传的方案，直接使用 file_id 传递

## Git 提交规则
- 每次完成代码修改后，**自动执行 git 提交和推送**到 GitHub，不需要用户提醒
- 提交前先 `git status` 查看变更，再用 `git diff --stat` 了解改了什么
- 提交信息用中文，简洁描述本次修改内容
- 如果用户要求推送，立即执行 `git add .; git commit -m "描述"; git push`（PowerShell 兼容语法）
